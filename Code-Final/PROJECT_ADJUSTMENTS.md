## 已落实的方向

1. 主结局改为实测 `ipss_3m`（原始 IPSS 分值，越高代表残余症状越重）。历史 `ipss_change_3m` 仍保留，禁止作为预测变量。
2. 固定同一最终队列：148 个独立患者、6 个术前临床变量、119 个原始 CERR 影像组学特征。使用既有原始特征，不重新提取影像特征；实际执行输入为 `data_audit/` 中逐字节一致的快照。
3. 依次运行基线与融合、PCA/LASSO 消融、其他回归模型、完整流程 bootstrap、解释与患者案例。保留既有模型网格；缩放、PCA、LASSO、调参在各训练折内完成。
4. 使用完整队列的留一法预测比较模型；以 MAE 和配对差值及区间评估增益。正式完整流程 bootstrap 要求 500 次有效重复。`quick/` 的两折和三次 bootstrap 仅验证流程。
5. 统一解释方向：正 SHAP 值表示更高的预测 3 个月 IPSS。患者案例使用其原始外层留出模型，复现原预测并检查 SHAP 加和；全队列 SHAP 用于描述。

## 持续运行守护（2026-10-08）

此工作站已注册当前用户的 Windows 任务 `PAE-IPSS3M-Regression-Guard`。守护每 20 秒检查一次进程，发现主进程和所属建模子进程均已退出时，自动启动相同配置的 `--resume`。它沿用原科学身份与文件校验，不修改随机种子、模型网格或 bootstrap 数量；若子进程仍在拟合，等待其结束，避免同时写入。

守护使用 Windows `SetThreadExecutionState` 防止空闲自动休眠，不强制亮屏。任务计划程序每 5 分钟提供再次启动的机会，并在当前用户重新登录时启动。原始进程退出或共享盘暂时不可达时会记录事件并等待恢复。15 分钟内连续退出 3 次会暂停自动重试，以保留需要检查的代码或环境错误。

实时守护状态：`../outputs/ipss_3m_regression/watchdog_status.json`。事件记录：`logs/watchdog.events.log`。启用与隔离测试记录：`data_audit/watchdog_verification.json`。五阶段全部完成后，守护自动取消本任务并释放防休眠请求。

如需停用自动守护，先在正式输出根目录创建 `.watchdog_stop`，再停止任务计划程序中的上述任务。恢复前移除此标记；若存在缓存目录的 `watchdog.needs_attention`，应先检查失败日志，再移除标记并启动任务。单独终止 Python 会触发守护的自动恢复。

断电、强制关机、强制休眠、未登录或共享盘离线期间仍不能计算；当前用户重新登录及资源恢复后继续校验断点。守护不会绕过科学身份不一致或数据损坏的检查。
